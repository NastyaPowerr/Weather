## Проект "Погода"

Веб-приложение для просмотра погоды.

Любой пользователь может искать разные локации. Для добавления локации в свой список необходимо авторизироваться.
После этого на главной странице можно будет просматривать погоду для выбранных локаций.

### Деплой (до 26.05.2026):

[http://85.198.67.210:8080/](http://85.198.67.210:8080/)

### Стек технологий:

* Java 17
* Spring MVC (без Spring Boot) 7.0.6
* PostgresSQL, Hibernate, Hikari
* Flyway
* SLF4J
* Junit, Mockito, Spring Tests

### Возможности приложения:

- регистрация и авторизация пользователей;
- поиск локаций по названию с помощью сервиса [OpenWeatherMap API](https://openweathermap.org/);
- возможность добавления и удаления локаций авторизированному пользователю;
- просмотр погоды добавленных локаций с помощью сервиса [OpenWeatherMap API](https://openweathermap.org/);
- возможность выйти с аккаунта, тем самым завершив сессию.

### Особенности:

- ручная реализация сессий без Spring Boot;
- используется BCrypt для хэширования паролей;
- добавлен аспект для логов;
- добавлена ежедевная очистка сессий с помощью @Scheduled;
- параллельные вызовы API погоды;
- использованы MapStruct, Lombok, Jackson и т.д. для уменьшения boilerplate кода и чистоты в целом.

### Кэш:

Использованы возможности кэширования:

- для поиска локаций (кэш сбрасывается ежедневно) для уменьшения кол-ва запросов обращений к внешнему сервису;
- для списка локаций пользователя и сессий пользователя с целью уменьшения запросов к БД.

Данные погоды не стала кэшировать, потому что они часто обновляются и, по моему мнению, пользователю всегда интересна
актуальная погода. Хотя также понимаю, что можно поставить кэш на 5 минут для популярных локаций.

По моим подсчётам, работа с кэшем позволила уменьшить кол-во запросов к БД и к внешнему сервису на ~45%.

### Для запуска:

1. Клонировать проект.
2. Выполнить сборку проекта с артефактом `.war`.
3. На виртуальном сервере установить JRE, PostgresSQL, Tomcat.
4. Создать базу данных и пользователя PostgresSQL.
5. Установить переменные окружения (в соответствии с файлом application-dev/prod.properties):

``` 
   db.username=${USERNAME}
   db.password=${PASSWORD}
   weather.api.key=${WEATHER_API_KEY}
```

6. Развернуть `.war` артефакт.
7. Приложение должно быть доступно по адресу [http://ВАШ_АЙПИ:8080/]().

валидация, тем меньше людей захотят протестировать учебный пет-проект, поэтому делать требования для сложного пароля,
